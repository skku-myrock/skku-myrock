# 모여락 홈페이지

성균관대학교 중앙 밴드 동아리 모여락. **Cloudflare Pages(정적 홈페이지 및 관리자 API)** + **Firebase Auth/Firestore(Spark 무료)** 구성.

- 회원용 홈페이지: Cloudflare Pages 프로젝트의 `*.pages.dev` 주소
- 인증: 기존 Firebase Authentication 유지 (학번 + 비밀번호)
- 데이터: 기존 Firestore 유지
- 역할별 부원 관리 API: Cloudflare Pages Functions `/api/members/*` (기존 Firebase Cloud Functions는 사용하지 않음)

## 1. Cloudflare Pages 최초 연결

Cloudflare Dashboard → **Workers & Pages → Pages → Connect to Git**에서 GitHub `skku-myrock/skku-myrock` 저장소를 연결합니다.

| 항목 | 설정 |
|---|---|
| Project name | `skku-myrock` (사용 가능한 경우) |
| Production branch | `main` |
| Root directory | 저장소 루트 `/` |
| Framework | React (Vite) |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Node.js | 22 이상 |

이 저장소의 루트 `functions/api/members/`는 **Cloudflare Pages Functions**입니다. Git 통합 배포 시 Pages가 이 경로를 인식해 `/api/members/list`, `/api/members/sessions`, `/api/members/details`, `/api/members/preview`, `/api/members/register`, `/api/members/permissions`, `/api/members/reset-password`, `/api/members/delete`, `/api/members/purge` API를 배포합니다.

`public/_routes.json`은 Vite가 `dist/_routes.json`으로 복사합니다. **`/api/*`만 Pages Functions 요청으로 집계**하고 HTML/CSS/JS/정적 이미지 요청은 Pages 정적 자산으로 제공하도록 지정합니다.

기존 Firebase Hosting GitHub Actions는 제거했습니다. 예전에 배포된 `skku-myrock.web.app` 주소는 Firebase Hosting에서 수동으로 삭제하지 않는 이상 그대로 남아 있을 수 있지만 **최신 변경 사항은 Cloudflare Pages에 배포**합니다.

### Git 통합 확인

Cloudflare Pages 프로젝트 → **Deployments**에서 `main` 최신 커밋 배포가 **Success**인지 확인하세요. 설정이 `workers.dev`가 아니라 **Pages 프로젝트**인지도 확인합니다.

### 배포 확인용 주소

Pages에서 실제 할당한 주소를 사용해 `https://<프로젝트>.pages.dev/api/health`에 접속합니다. 다음과 같은 JSON이 표시되면 Pages Functions가 배포된 것입니다.

```json
{"service":"myrock-pages-api","deployed":true,"firebaseSecretConfigured":false}
```

`firebaseSecretConfigured: false`는 관리자 서비스 계정 Secret이 없다는 뜻입니다. 대시보드에 `FIREBASE_SERVICE_ACCOUNT`을 저장하고 **재배포하면 true**가 되어야 합니다. 이 점검은 Secret 존재만 검사하며 실제 Firebase API 호출 성공까지 보장하지 않습니다. HTML 홈페이지가 나타나거나 404가 나오면 Pages Functions가 아직 배포되지 않았거나 빌드 설정을 확인해야 합니다.

## 2. Firebase 인증 도메인 추가

Firebase Console → Authentication → Settings → **Authorized domains**에 **실제 발급된** `<your-project>.pages.dev` 도메인을 추가합니다. 주소에 `https://`를 포함하지 않습니다.

기존 Firebase Auth 계정, 비밀번호, Firestore 문서는 이전하지 않고 그대로 유지합니다. 로그인은 Firebase JS SDK로 처리하므로 기존 `authDomain` 설정을 유지합니다.

## 3. Cloudflare 비밀키 연결 (필수)

운영진 API는 Firebase 서비스 계정으로 Google REST API를 호출합니다. 학번 변경은 Auth 이메일도 업데이트해야 하고 회장단의 비밀번호 초기화·회원 삭제에는 Firebase Authentication Admin의 사용자 업데이트·삭제 IAM 권한이 필요합니다. **클라이언트 코드나 GitHub에 서비스 계정 키를 절대로 저장하지 마세요.**

1. Firebase 프로젝트 `skku-myrock`에 접근 가능한 서비스 계정을 준비합니다. 최소 권한 관리를 위해 **Firebase Authentication Admin** 및 **Cloud Datastore User** 등 계정 생성·조회·삭제와 Firestore 문서 조회·생성·수정에 필요한 IAM 역할만 부여하는 전용 서비스 계정을 권장합니다.
2. 서비스 계정 JSON은 자신의 컴퓨터에만 저장합니다. 현재 Firebase Admin SDK에서 사용한 키를 임시로 재사용할 수도 있지만, 장기 운영에는 전용 키를 권장합니다.
3. Cloudflare → **Workers & Pages → 해당 Pages 프로젝트 → Settings → Variables and Secrets → Add**에서 다음을 생성합니다.

   | 이름 | 설정 | 값 |
   |---|---|---|
   | `FIREBASE_SERVICE_ACCOUNT` | **Encrypt/Secret** | 서비스 계정 JSON 전체 내용 |
   | `FIREBASE_API_KEY` | 일반 환경 변수 (선택) | Firebase 웹 API key. 코드에 기존 공개 Firebase 구성값을 기본으로 사용 |

4. **Production** 환경에 설정하고 **새 배포를 실행**해야 Functions 런타임에 반영됩니다. Preview 배포도 테스트하려면 Preview 환경에 별도로 지정해야 할 수 있습니다.
5. Cloudflare Pages 무료 할당량에 맞춰 각 요청에서는 회원 **최대 5명**씩 처리하며, CSV가 60명인 경우 웹이 자동으로 여러 요청으로 나눠 처리합니다.

서비스 계정 JSON 파일을 ChatGPT 대화, GitHub, 공개 페이지나 Cloudflare 일반 평문 변수에 붙여 넣지 마세요. **Secret**으로만 설정합니다. 계정 소유자 또는 개발 담당자만 이 설정을 관리하고, 일반 운영진에게 키를 넘기지 않습니다.

> **주의:** 비밀키가 없거나 Google Cloud IAM 권한이 부족하면 홈페이지 정적 페이지는 표시되지만 회원 관리 API는 실행되지 않습니다. 이 저장소 변경만으로 사용자의 Cloudflare Secret과 Firebase Authorized domains를 대신 설정할 수 없습니다.

## 4. CSV 부원 등록 절차

로그인한 회장단이 **부원 관리 → 신입부원 등록**에서 다음 3단계를 수행합니다.

1. **CSV 추가:** 양식을 받거나 UTF-8 CSV 파일 선택 (한 번에 최대 60명).
2. **추가될 명단 확인:** 실제 생성에 앞서 Firebase에서 기존 학번 존재 여부를 조회하고 **신규 등록 예상 인원·기존 계정 수·학번·이름·기수·세션·직책 전체를 표로 확인**. 이 단계에서는 어떠한 회원도 생성하지 않음. 다른 파일로 바꿀 수 있음.
3. **등록 실행 → 등록 완료:** 웹이 5명 단위로 요청을 처리하며 진행률을 **0~100%**로 표시하고, **신규 생성/기존 계정/실패** 결과를 구분합니다. 새 계정의 초기 비밀번호는 학번 10자리와 같습니다.

양식 예시:

```csv
학번,이름,기수,세션,직책
2026300001,홍길동,29,"기타,베이스",
2026300002,김모여,29,드럼,"장비관리,홍보부장"
```

영문 헤더 `studentId,name,generation,sessions,positions`도 지원합니다. **세션과 직책의 여러 값은 쉼표로 구분**합니다. `"기타,베이스"`와 `"기타, 베이스"`는 모두 `기타`·`베이스`로 해석하며, 결과를 화면에 표시할 때는 `기타,베이스`처럼 쉼표 뒤 공백이 없는 표준 형식으로 표시합니다. 직책도 동일합니다. **CSV의 열 구분자도 쉼표이므로 여러 값을 담은 셀 전체를 반드시 큰따옴표로 감싸야 합니다.** (예: `"보컬파트장,홍보부장"`)

- **실제 회원 생성은 2단계에서 관리자가 등록 실행을 누른 뒤에만 진행됩니다.** 신규/기존 계정 수는 파일을 확인한 시점의 예상치이며, 동시에 다른 관리자가 등록하면 실제 결과가 달라질 수 있습니다.
- 새 계정은 언제나 `role: member`, `handoverAccess: false`. `generation`과 `positions`는 표시용 데이터입니다.
- 기존 학번이 이미 있으면 계정·프로필·비밀번호·권한을 수정하지 않고 건너뜁니다.
- 통신 장애 시 결과를 확인할 수 없는 계정이 존재할 수 있으므로 **무작정 같은 명단을 재시도하지 말고 회원 명단과 관리자 로그를 확인**하세요.
- **신규 생성 계정**은 초기 비밀번호가 **본인 학번(10자리)**입니다. 초기 비밀번호 CSV 파일을 따로 내려받을 필요는 없습니다. 기존 계정의 비밀번호는 변경하지 않습니다. 로그인 문제가 생기면 운영진에게 연락하도록 안내합니다. 비밀번호는 로그인 후 **내 정보 → 비밀번호 변경**에서 본인이 변경할 수 있습니다.
- 계정 생성과 Firestore 프로필 생성은 별도 Google 서비스 작업이므로 일부 실패가 가능하며, 서버는 신규 계정 롤백을 시도합니다.

부원 관리에서 **파트장·실무단에게는 부원 명단 탭만**, **회장단에게는 부원 명단 및 신입부원 등록 탭**을 표시합니다. 부원 명단은 Firestore의 `name asc, __name__ asc` 정렬 인덱스를 사용해 **처음 30명만 조회**하고, 하단으로 스크롤하면 `IntersectionObserver`가 다음 30명을 자동으로 불러옵니다. 전체 이름순으로 정렬된 결과를 페이지별로 받아 한 화면에 이어 붙입니다. 스크롤 중 목록 요청에 실패하면 자동 재시도를 멈추고 사용자에게 재시도 버튼을 제공합니다. 한국어 완성형 이름은 일반적인 가나다순으로 표시되지만 Firestore 문자열 정렬은 완전한 한국어 사전 정렬과 일부 다를 수 있습니다. **검색은 아직 불러온 명단에만 적용됩니다.** 수정 기능은 부원 행 아래에 바로 표시되며 별도 권한 관리 탭은 없습니다.

## 5. 부원 관리 권한

서버는 Firebase ID 토큰 및 Firestore 프로필을 **요청마다 다시 검증**합니다. 화면에서 버튼을 숨기는 것 외에도 서버 API에서 역할별로 거절합니다.

| 기능 | 파트장 | 실무단 | 회장단 |
|---|---|---|---|
| 부원 명단 전체 조회 (가나다순) | 가능 | 가능 | 가능 |
| 타 부원 세션 수정 | 가능 | 가능 | 가능 |
| 이름/학번/기수/직책 수정 | 불가 | 가능 | 가능 |
| CSV·개별 부원 추가 | 불가 | 불가 | 가능 |
| 권한 / 인수인계 지정 | 불가 | 불가 | 가능 |
| 비밀번호 초기화 (현재 학번 10자리) | 불가 | 불가 | 가능 |
| 부원 삭제 (Auth 계정 + Firestore 프로필) | 불가 | 불가 | 가능 |

**OB 운영진**은 `handoverAccess: true`이면서 `role: member`이면 내 정보의 권한에 OB 운영진으로 표시하지만, **부원 명단 조회 및 수정 권한은 부여하지 않습니다.** 현재 최고관리자만 기존 custom claim과 Firestore flag를 함께 검사해 회장단 수준으로 관리할 수 있습니다.

**내 정보 → 권한**은 `회장단`, `실무단`, `파트장`, `OB 운영진`, `일반부원` 중 한 가지로 표시합니다. 직책은 별도 필드로 표시합니다. 부원 명단의 권한 수정에서 **인수인계 내용 접근 권한 설정** 체크박스는 운영 권한을 `일반부원`으로 선택했을 때만 표시됩니다. 체크하면 내 정보의 권한에는 `OB 운영진`으로 표기됩니다. 파트장·실무단·회장단은 별도 체크 없이 인수인계 내용에 접근할 수 있으며, 다른 운영 권한을 선택할 때 OB 전용 플래그는 해제됩니다.

학번을 수정하면 `학번@members.skku-myrock.firebaseapp.com`로 되어 있는 Firebase Auth 로그인용 이메일까지 변경하고, Firestore 저장에 실패하면 Auth 값을 되돌리도록 시도합니다. 학번 변경 시 **비밀번호는 자동 초기화되지 않습니다.**

회장단이 비밀번호를 초기화하면 해당 부원의 비밀번호가 **현재 학번 10자리**로 바뀝니다. 계정 삭제는 학번 재입력 확인을 요구하며 시스템 관리자와 본인 계정은 삭제할 수 없습니다. 삭제 작업은 Auth와 Firestore가 서로 다른 서비스이므로 오류 발생 시 복구 확인이 필요할 수 있습니다. **하위 컬렉션/다른 게시물 데이터까지 자동 정리하는 기능은 포함하지 않습니다.**

비밀번호 변경 화면에서는 사이트 자체의 최소 길이·조합 제한을 두지 않습니다. 단, **Firebase Auth 서버 자체의 최소 6자 제한**은 유지됩니다.


- `role`: `member`, `part_leader`, `staff`, `president` (기수로 자동 변경되지 않음)
- `positions`: 표시용 직책 목록
- `handoverAccess`: 다른 권한과 독립적인 인수인계 접근 여부

Firebase 로그인 토큰 서명·대상 프로젝트·만료 시간 및 Firestore의 현재 회장단 권한을 **Cloudflare 서버에서 검증**합니다.

현재 개발용 최고관리자 계정은 유지되며, **최고관리자를 새로 발급하거나 수정하는 API는 제공하지 않습니다.** 웹에서 자기 자신이나 기존 최고관리자 계정의 권한 변경을 금지합니다.

세션 수정·자기 비밀번호 변경은 기존 Firebase SDK에서 진행합니다. 신규 회원에게 학번과 동일한 초기 비밀번호를 지정하는 방식은 추측 가능하므로, 계정에 문제가 있다면 운영진에게 문의하고 필요한 경우 본인이 변경하는 것을 권장합니다. 자동 최초 로그인 변경은 강제하지 않습니다. 현재 이메일은 실제 수신함이 아닌 `학번@members.skku-myrock.firebaseapp.com` 주소로, 이메일 재설정은 지원하지 않습니다.

Firestore 보안 규칙 `firestore.rules`는 자기 프로필만 읽고 세션만 직접 수정하도록 제한합니다. 운영진 작업은 보안 규칙을 우회할 수 있는 서비스 계정으로 수행하므로 **Cloudflare Functions 내부에서 관리자 권한을 반드시 확인합니다.**

### 개발용 최고관리자 명단 초기화

Firebase ID 토큰의 `superadmin: true` **서명된 사용자 지정 클레임과** 해당 사용자의 Firestore `superadmin: true` 필드가 **모두 확인되는 계정에만** 계정 드롭다운의 **로그아웃 바로 아래 빨간색 '명단 초기화'**가 표시됩니다. 보통 회장단이나 OB 운영진 계정에는 보이지 않습니다. 휴대폰 메뉴에서도 같은 조건으로 표시합니다.

- 버튼 클릭 뒤 브라우저 확인창에서 **확인**을 누른 경우에만 실행됩니다.
- 서버는 이 두 최고관리자 조건을 독립적으로 재검증하며, 프런트엔드가 삭제 대상 UID를 전달할 수 없습니다.
- 본인의 Firestore `users/{uid}`와 Firebase Authentication 계정은 보존하고 **다른 부원의 프로필 및 연동된 Auth 계정**을 최대 **5명씩** 처리합니다. 삭제 결과를 표시하고 중간 실패가 발생하면 중단합니다. 다시 실행할 경우 남은 명단부터 진행합니다.
- 다른 `superadmin: true` 프로필이 발견되는 경우 보호를 위해 작업을 중단합니다.
- Firebase Auth 계정 없이 프로필만 남은 경우에는 해당 프로필을 정리합니다. **프로필 없이 Firebase Auth에만 존재하는 계정은 이 기능에서 검색/삭제하지 않습니다.**
- 이 기능은 Cloudflare의 무료 실행/외부 요청 한도를 고려한 개발용 관리 도구입니다. **실제 부원 명단이 만들어지기 전에 제거하거나 접근 정책을 재검토하세요.**
- Firestore 문서 삭제는 **하위 컬렉션을 재귀적으로 제거하지 않습니다.** 현재 구현에서 별도의 하위 컬렉션 생성 기능은 없지만, 수동으로 만든 하위 컬렉션이나 앞으로 추가하는 When2meet·게시물·장비 대여 기록은 이 명단 초기화로 삭제되지 않을 수 있습니다.

### 수동 명단 초기화 후 점검

1. Firebase Console → **Authentication → Users**에서 보존할 최고관리자 외에 이전에 발급한 부원 계정이 남았는지 확인합니다.
2. Firestore → **Data → users**에서 보존할 최고관리자 외 문서가 남았는지 확인합니다. 문서 아래 하위 컬렉션을 직접 생성했던 경우 개별 확인이 필요합니다.
3. 테스트 중 다른 Firestore 컬렉션, Cloud Storage 업로드 파일, 외부 서비스 데이터 등을 생성한 경우 해당 데이터는 각각 별도로 확인합니다.
4. `FIREBASE_SERVICE_ACCOUNT` 서비스 계정 키와 최고관리자의 Firebase 사용자 지정 클레임은 삭제할 필요가 없습니다. 명단 초기화는 Firebase 프로젝트 자체를 삭제하는 작업이 아닙니다.

- `Escape` 키와 닫기 버튼으로 복귀할 수 있으며 닫으면 이전에 선택했던 앨범 카드로 키보드 포커스를 돌려줍니다.

## 공지사항 (Firestore)

- 기존 소스코드에 포함된 예시 공지 4건을 제거했습니다. 공개 `/api/notices`에서 Firestore `notices/{id}` 문서를 가져와 홈·목록·상세 화면에 표시합니다.
- 파트장 이상은 `/news/write`에서 제목·분류·텍스트·이미지·슬라이드를 편집하고 **발행**할 수 있습니다. 누구나 작성자를 볼 수 있으며, 파트장 이상에게는 상세 화면의 **관리 → 수정하기 / 삭제하기** 메뉴가 표시됩니다.
- 수정 화면은 글쓰기와 같은 컴포넌트를 사용하며, 작성자와 최초 게시일은 수정해도 유지합니다. Firestore `updateTime`을 확인하여 충돌을 방지합니다. 삭제할 때 Firestore 문서는 삭제하지만 GitHub에 업로드된 이미지는 즉시 삭제하지 않습니다.
- 파일 선택 시 로컬에서만 미리보기하며 발행·저장 시에만 업로드합니다. 새 파일은 `/api/images/batch`에 최대 12장·총 16MB씩 전달하고 배치 하나당 GitHub 커밋 하나를 만듭니다. Pages 이미지 배포 전에는 URL이 일시적으로 보이지 않을 수 있습니다.
- 슬라이드당 최대 20장이며 사진 원본은 JPG/PNG/WebP 최대 30MB를 선택할 수 있습니다. **발행·저장 시 브라우저에서 최대 2560px로 크기를 줄이고 WebP로 압축**한 뒤 서버의 기존 파일당 5MB / 배치당 16MB 제한 내에서 GitHub에 커밋합니다. 작은 파일은 원본을 그대로 둘 수도 있습니다. GIF 파일 업로드는 지원하지 않습니다. 움직이는 WebP는 프레임 손실 방지를 위해 재인코딩하지 않으며 5MB 이하에서만 지원합니다. **자동 압축된 이미지가 원본을 대체하지 않으므로 원본 사진은 별도로 보관해야 합니다.** 외부 URL을 붙여넣은 이미지는 압축하지 않습니다. 원본 픽셀 비율에 따른 크기 계산을 사용합니다. 가로·세로 입력은 편집 중 자유롭게 지울 수 있고, 포커스 해제 후 유효값인 경우에만 미리보기 크기에 반영됩니다. 기존 슬라이드 순서 변경 UI를 유지합니다. 여러 배치가 필요한 경우 GitHub 커밋도 여러 건 생깁니다.
- 서버에서 Firebase ID 토큰과 Firestore의 파트장 이상 권한을 작성·수정·삭제 요청마다 검증합니다. GitHub 인증 Secret은 서버에만 보관합니다.

## 후원 · 회계 (Firestore 후원 기록 관리)

- 메인 `/finance`는 후원 소개·계좌 안내·비공개 후원 안내·두 내역 상세 페이지로 구성됩니다. 후원 계좌는 기본값 **농협 302-0000-0000-31 / 나재원**을 공개 화면에 표시합니다. 검증된 **회장단(`president`) 이상**만 `정보 수정` 버튼을 볼 수 있고, Firebase 토큰과 Firestore 권한을 검증하는 `/api/finance/account`에 제출하면 `financeSettings/donationAccount`에 저장됩니다. 수정 시 버전 충돌을 검사하며, 저장된 계좌가 있으면 기본값보다 저장된 값을 우선합니다.
- `/finance/donations`의 **전체 후원 내역**은 공개 API `GET /api/donations/public`을 통해 **후원일, 표기용 후원자명, 후원금액**만 반환합니다. 학번과 원본 익명 여부, 익명자 명단은 절대 응답에 포함하지 않습니다. 후원자명이나 학번 중 하나라도 비어 있거나 CSV `익명여부`가 `o`이면 `익명`으로 표시합니다.
- **내 후원 내역**은 Firebase 로그인 토큰을 검증하고 Firestore `users/{uid}.studentId`를 조회한 뒤 해당 10자리 학번과 일치하는 후원 기록만 서버에서 골라서 **후원일·후원금액** 두 열로 보여줍니다. 해당 내역이 정상 조회되면 **지금까지의 내 총 후원 금액**도 누적 합산해 표시하며, 내역이 없으면 0원으로 표시합니다. 동명이인을 고려해 이름으로 추정하거나 익명 처리 여부로 제외하지 않습니다. 학번 미확인 후원은 본인 확인이 불가능하므로 조회되지 않습니다.
- `/finance/donations/manage`은 **실무단(`staff`)·회장단(`president`)·검증된 superadmin**에게만 열립니다. Cloudflare API도 로그인 토큰과 현재 Firestore 권한을 매 요청 다시 검증합니다. CSV 일괄 추가(확인 단계에서 **가장 이른 후원일 ~ 가장 늦은 후원일** 표시), 개별 후원 추가 및 **목록 행 내부 수정·저장·취소(고정 열 너비와 나란히 정렬되는 버튼)**, **전체 내역 CSV 다운로드**, 익명자 명단 관리 기능이 있습니다. 파트장/일반부원/OB 운영진은 이용할 수 없습니다.
- CSV 양식 다운로드 버튼을 제공하며, 날짜와 익명 표시 주의사항을 파일 선택 아래에 안내합니다. CSV 헤더는 정확히 **`후원일,후원자명,학번,후원금액,익명여부`**이며 날짜는 `YYYY-MM-DD`, 학번은 빈칸 또는 10자리 숫자, 후원금액은 양의 정수입니다. 이름·학번은 각각 비어 있어도 됩니다. `익명여부`는 소문자 `o`만 익명으로 간주하며 `x`나 빈칸 등 다른 값은 `x`로 정규화합니다. CSV 파일은 1,000건 이하/200KB 이하를 허용하고 40건씩 서버 배치 추가합니다. **추가는 기존 데이터를 대체하지 않으며 중복 업로드에도 동일 기록이 추가**될 수 있으므로 확인창과 목록 점검이 필요합니다.
- 익명자 명단은 별도 Firestore `financeSettings/anonymousDonors`에 보관합니다. **이름과 숫자 10자리 학번을 모두 등록해야만** 해당 학번의 모든 후원을 익명 표시합니다. 한쪽이 비어 있으면 서버가 저장을 거절하며, 예전에 저장된 불완전한 명단 항목도 익명 표시 규칙에 적용하지 않습니다. 저장을 완료한 명단 행은 입력 박스 대신 이름·학번 텍스트와 **제외** 버튼만 표시합니다. 제외를 누르면 즉시 삭제하지 않고 **이름·학번에 취소선을 표시하며 제외 취소 버튼을 제공**합니다. 실제 명단 변경은 저장 성공 후 반영되며, 모든 변경을 되돌리거나 저장할 내용이 없으면 **익명자 명단 저장 버튼이 명확히 흐려진 비활성 상태**로 표시됩니다. **익명자 명단 저장** 결과(이름/학번 유효성 검사 실패 및 저장 완료)는 상단이 아닌 익명자 명단 저장 버튼 바로 옆에 표시하며 모바일에서는 아래 줄로 표시합니다. 회원 등록·수정·회계 CSV 저장·익명자 명단 저장·계좌 정보 변경·로그인·비밀번호 변경·관리 데이터 초기화 등 비동기 작업 동안에는 **활성화 여부와 무관하게 화면 어디에서든 대기 커서**를 표시합니다. 버튼 비활성화 기능은 그대로 유지하고, 작업 중이 아닌 비활성 버튼에는 금지 커서 대신 기본 커서를 적용합니다. 학번 미확인 후원은 애초에 공개 화면에서 익명입니다. 따라서 개별 CSV에는 원본 이름과 학번을 유지하면서 웹 공개용 값만 익명 처리합니다.
- 후원 데이터는 Firestore `donations/{id}`에 저장하며 이름·학번을 포함하므로 서버 관리자 API 외에는 읽을 수 없습니다. `firestore.rules`의 전체 차단 규칙을 유지합니다. 개별 수정에는 Firestore 문서 버전 검사를 사용합니다. CSV 다운로드는 운영진 계정에만 제공되는 **원본 전체 정보**이므로 외부 공유를 주의해야 합니다.
- 최고관리자(superadmin)는 계정 드롭다운의 **명단 초기화 아래에 후원 · 회계 초기화** 버튼을 볼 수 있습니다. 한 번의 경고 확인창에서 확인을 누르면 Firestore 후원 기록 및 회비 집행 거래 기록을 각각 최대 20건씩 순차 삭제하고, 두 거래 컬렉션이 비워진 후 익명자 명단을 삭제합니다. 후원 계좌 설정은 삭제하지 않습니다. 회원 계정·프로필·공지사항·기존 명단 초기화 기능에는 영향이 없습니다. **영구 삭제이며 복원 기능은 없습니다.**
- **초기 CSV는 개인정보(실명과 학번)가 들어 있어 공개 GitHub 저장소에 시드 데이터로 커밋하지 않았습니다.** 첨부된 `donate(1).csv`의 내용(8건)은 아직 운영 Firebase에 저장되었다고 보장할 수 없습니다. 배포 후 실무단 이상으로 로그인해 **후원 내역 관리 → CSV 파일 선택 → 8건 추가**를 한 번 수행해야 초기 데이터가 Firestore에 생성됩니다. 재업로드하면 중복되므로 유의하세요. 익명자 명단은 별도로 편집할 수 있습니다.
- `/finance/expenses`는 **거래일시, 거래구분(입금/출금), 거래금액, 거래 후 잔액, 거래내용** 다섯 열로 은행 계좌의 입출금 전체 기록을 표시합니다. 입금과 출금 모두 빠짐없이 등록할 수 있으며, 데이터는 Firestore `expenseTransactions/{id}`에 저장됩니다. 실무단 이상에게만 **회비 집행 내역 관리** 버튼 및 `/finance/expenses/manage` 경로를 제공하고, 서버도 권한을 재검증합니다. 관리 화면에서 직접 거래를 추가하거나 기존 표의 행 안에서 수정·저장·취소할 수 있습니다. 관리용 **전체 거래 CSV 다운로드**를 지원하지만, **CSV 파일 업로드**도 지원합니다. 후원 내역과 같은 흐름으로 파일 선택→날짜 범위·건수 확인→추가 확인→Firestore 일괄 등록을 수행하며, 한 파일은 1,000건/200KB 이하로 제한하고 서버에 20건씩 배치 저장합니다. 파일을 재업로드하면 동일 거래가 중복으로 추가될 수 있습니다. 두 회계 관리 화면 모두 CSV 파일 선택 옆의 **양식 내려받기**에서 헤더와 예제 값이 포함된 CSV를 받을 수 있습니다. 후원 CSV 날짜는 `2026-10-14`, 거래 CSV 일시는 `2026-10-14 15:30` 형식을 사용해야 합니다. 후원 익명 여부에는 소문자 `o`만 인정합니다.
- 거래 입력은 `YYYY-MM-DDTHH:mm` 형식의 거래일시, 입금/출금 중 하나, 원 단위 양의 거래금액, 0원 이상의 거래 후 잔액, 필수 거래내용(최대 240자)을 검증합니다. 은행과 실시간 연동되지 않으므로 운영진이 원장과 대조하여 입력해야 합니다. 이미 저장된 거래 금액에 따라 잔액을 자동 계산하거나 잔액 일관성을 서버에서 대조하지는 않습니다.
- 거래 내역 공개 조회 API와 운영진 전용 수정 API를 분리했습니다. 후원 계좌의 실제 입출금 여부를 검증하는 은행 API 연동은 아직 없습니다. 공개 실명에 대해서는 개인정보 처리/공개 동의 정책을 운영진이 확인해야 합니다.

## 합주 시간 조율 (현재 목록·상세 미리보기)

URL 직접 접근, 브라우저 뒤로·앞으로 가기, 목록으로 돌아가기 등을 지원합니다.

## 공지사항 이미지 입력 및 하단 알림

- 공지사항 작성 화면의 **이미지 추가**, **슬라이드에 사진 추가**, **슬라이드로 사진 추가** 버튼은 URL 입력과 다중 파일 선택 박스를 펼칩니다. URL을 추가하면 이미지 하나가 삽입되고, 이미 존재하는 슬라이드에 추가하면 같은 슬라이드에 포함됩니다. 파일을 여러 장 선택하면 기존과 동일하게 슬라이드로 묶습니다. URL은 HTTPS만 지원하며 이미지는 로컬에서 미리봅니다. 실제 발행·저장 시에만 이미지와 공지사항 내용을 저장합니다.
- 동아리 소개 수정과 후원 내역 관리의 익명자 명단 및 계좌 정보 저장 결과와 오류 메시지는 화면 하단에 고정되는 **닫기 가능한 팝업**으로 표시합니다. 이전 외부 버킷 연결은 더 이상 사용하지 않습니다.

## 이미지 저장소 (Organization)

사진 업로드는 `skku-myrock/myrock-images` 비공개 저장소에 저장합니다. **`site/`는 메인·동아리 소개·운영진 프로필처럼 교체 가능한 사진**, **`notices/`는 장기 보관하는 공지사항 사진**, **`gallery/`는 포토존 사진**입니다. 공지사항 새 업로드는 `notices/`만 사용하며 기존 URL을 수정 없이 유지합니다. Cloudflare Pages 이미지 전용 프로젝트는 해당 저장소의 루트 디렉터리를 정적 배포하도록 연결해야 합니다.

홈페이지 Pages Functions의 서버 전용 Secret `GITHUB_IMAGES_TOKEN`에는 이미지 저장소에만 `Contents: Read and write` 권한이 있는 GitHub App 설치 토큰 또는 fine-grained 토큰을 설정합니다. `MYROCK_IMAGES_PUBLIC_BASE_URL`에는 이미지 Pages의 HTTPS 공개 기본 주소(예: `https://images-example.pages.dev/`)를 설정합니다. 브라우저에 GitHub 자격 증명을 제공하지 마세요. GitHub에 커밋한 후 Pages 배포가 완료되기 전에는 사진 URL이 즉시 표시되지 않을 수 있습니다.

`/api/about/image`는 기존 화면에서 POST할 경우 새 GitHub 업로드 API로 전달하는 호환 경로입니다. GET 버킷 조회 기능은 제거했습니다. 권장 업로드 API는 `/api/images/batch`이며 기존 단일 이미지 API `/api/images/upload`도 GitHub만 사용합니다.

## 최고관리자 초기화 및 이미지 정리

- 로그인 계정의 **서명된 Firebase 최고관리자 클레임** 및 **Firestore 최고관리자 플래그**가 모두 유효할 때만 명단·회계·공지·소개·에셋 초기화를 표시하고 API에서도 검증합니다. 모든 초기화 버튼은 **한 번의 경고 확인창**만 표시하며, 확인 시 즉시 요청합니다. 별도의 문구 타이핑은 요구하지 않습니다.
- **공지사항 초기화**: `/api/notices/purge`가 Firestore `notices` 컬렉션을 요청당 최대 20개씩 삭제합니다. 마지막 배치에서 GitHub `notices/`의 최신 사진도 `.gitkeep`만 남기고 정리합니다. 실패하면 다시 실행하여 나머지 문서 및 사진 정리를 마칠 수 있습니다.
- **모여락 소개 초기화**: `/api/about/reset`은 운영진 정보(28기 운영진 8명)와 **1998년 창단, 2023년 중앙동아리 승격** 연혁만 초기화합니다. 기존 메인 페이지 사진·동아리 소개 사진 URL은 유지하고, 운영진 사진도 같은 이름을 우선 매칭해 유지하며 이름이 달라진 경우 원래 표시 순서를 기준으로 이어받습니다. GitHub 이미지는 변경하지 않습니다.
- **에셋 초기화**: `/api/images/reset`은 GitHub `site/` 폴더를 비운 다음 Firebase Firestore `siteContent/clubIntroduction`의 **메인 페이지 사진(`homeImage`)·동아리 소개 사진(`heroImage`)·운영진 사진(`photoUrl`) URL만 빈 값으로 수정**합니다. 운영진 이름·직책·기수·연혁과 `gallery/`, `notices/`는 변경하지 않습니다. 이전 공지사항이 `site/` URL을 참조하는 경우 사진 유실 방지를 위해 실행을 거절하며, 먼저 해당 사진을 `notices/`로 이전해야 합니다. GitHub 정리 후 Firestore 쓰기에 실패하면 일부만 처리될 수 있으므로 다시 실행하세요. 파일 정리는 최신 Git 브랜치를 변경할 뿐 Git 이력과 Cloudflare CDN의 옛 직접 URL을 즉시 삭제하지는 않습니다.
- Git 이력에 남은 과거 파일이 영구 제거되는 것은 아닙니다. 위 작업은 최신 `main`에서만 이미지 파일을 제거합니다. 이미지 전용 Pages 배포의 전파는 비동기입니다.

## 저장·배포 역할

- **GitHub**: 공개 홈페이지 소스코드 `skku-myrock/skku-myrock`, 비공개 사진 원본 `skku-myrock/myrock-images`.
- **Cloudflare Pages 및 Pages Functions**: React 정적 홈페이지, 이미지 정적 배포, 서버 API, CSV 업로드 요청의 유효성 검사와 처리.
- **Firebase Authentication / Firestore**: 로그인, 권한, 공지사항/소개/후원·회계/부원 명단의 영속 저장. **CSV 파일의 행 데이터는 Cloudflare에 장기 저장되는 것이 아니라 Firestore에 저장됩니다.**
- 예전 이미지 버킷 연결은 앱 코드에서 참조하지 않습니다. Cloudflare 대시보드의 구버전 배포, 버킷 자체, 구형 변수/바인딩은 **운영 데이터 백업 후 별도로 해제**해야 합니다.

## 편집 화면 이탈 및 저장 확인

- 동아리 소개 수정과 공지사항 작성/수정은 실제 입력 내용이 변경된 상태에서 사이트 메뉴 이동·뒤로 가기를 시도하면 저장되지 않은 변경 사항에 대한 확인창을 표시합니다. 새로고침이나 브라우저 탭 닫기에는 브라우저가 제공하는 기본 이탈 경고창을 사용합니다.
- 동아리 소개 수정은 저장 완료 시 동아리 소개 페이지로 돌아가며, 기존과 같은 하단 성공 알림을 계속 표시합니다.
- 후원 계좌 정보 수정은 저장된 은행·계좌번호·예금주와 동일한 값일 때 저장 버튼을 비활성화하고, 성공 시 하단에 '저장을 완료했습니다.' 알림을 표시합니다.
